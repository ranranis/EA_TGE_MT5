# Feishu MT5 Signal Monitor

这是一个 Windows 后台运行的**飞书消息监控 + 老师点位 / M5 分析看板**，目标群为 `top-vip群`。默认 `mode=monitor`，不创建模拟订单，也不发送真实订单。原来的纸面模拟模块保留，只有显式配置为 `paper` 才运行。交易EA独立编译、由用户手动加载。

## v1.42（历史说明）：三层触价

正式文件固定为 `Experts/EA_T哥点位跟单.mq5` / `.ex5`。新增 `tge_execution.csv`（TGA6）一次性输出完整点位、大小区间和明确方向；老 `tge_ai_setups.csv` 保留给旧版本，升级前不会让旧 EA 误读新协议。重启监控后再手动重新加载同名 EA。

- 明确方向优先级8；声明的大小区间下沿多、上沿空，优先级6；中性地图从上方跌到点位做多、从下方涨到点位做空，优先级5。区间方向是用户约定规则，不冒充T哥原文方向。
- 以买单Ask、卖单Bid进入点位±1.00判断，每次0.02手、默认最多3笔。同一区域高优先级先执行；同级方向矛盾暂缓。无需MA/M5入场确认；保留新鲜报价、点差、逆向连续冲穿暂缓和成交对账。启动已在中性点位区域内、尚不知从哪边接近时等待离区。离开4.00至少5秒后可重入，消息重发或只改目标不能重复消费同次触价。
- 不再新增策略限价挂单。加载后先对账并撤销旧TGL策略挂单，真实成交的旧仓仍管理；手机标记是原有独立开关。离价超过原参数“挂单最大离价”（默认50）暂停本地候选，点位本身不按时间到期。
- 默认初始SL距离10、首批5、尾仓10；原文明示的SL/TP保留。在首批目标后，开仓以来完整M5均顺向则减半，夹反向或十字K则全平；还没有完整M5时用完整M1，顺向继续持有，犹豫退出。减半以真实Deal确认，余仓申请价格保本；来不及放置合法保本SL时申请退出余仓。价格保本不代表覆盖佣金或滑点。
- 三类点位集中显示在面板，统计和看盘功能保留。历史导入、撤回来源、待解析/待确认、断线或失效快照均不能成为新交易授权。

验证命令：`python -X utf8 -m unittest test_execution_feed test_teacher_scene test_deepseek_ai test_plan_preview test_layered_signals`（监控目录），`node _dev/tests/tge-touch-regression.cjs`（Experts目录）。合成测试验证程序分支，不等于盈利回测或真实券商成交验收。

## 一键全部启动 / 关闭

双击本目录的 `全部启动.cmd`：打开配置指定的MT5（已运行时不重复打开），解除全部停止和暂停状态，并启动后台监控；行情连接和消息同步会随后恢复。不修改MT5的算法交易权限或EA配置。

双击本目录的 `全部停止.cmd`：先等待监控和行情连接退出，再正常关闭配置指定的MT5。关闭状态会保留，登录启动任务也不会重新拉起；恢复时双击 `全部启动.cmd`。原有 `Stop.cmd` 仍只停止监控。关闭MT5期间本地EA停止运行，券商端已有SL/TP仍由服务器处理；此操作不主动平仓或撤单。如果终端弹窗阻止退出，会提示手动关闭，不强杀MT5。

## 看板与观察规则

双击 `Start.cmd` 通过 Windows 任务计划启动常驻服务（自动安装/更新本项目任务），再双击 `Dashboard.cmd`（只打开浏览器），或访问 **http://127.0.0.1:8765/**。页面展示后台心跳、飞书同步时间、最近50条消息、老师当前点位、M5蜡烛图、EMA20/50、ATR14和候选提示。群消息默认30秒轮询，分析每5秒更新，看板每3秒刷新。浏览器和 Codex 关闭后，后台仍独立运行。看板由常驻服务维护，监控子进程退出时保持页面在线，按5至60秒退避重启监控；Windows登录后也会自动启动。暂停保留看板，`Stop.cmd` 则停止整套服务。监控日志在 `logs/monitor.log`，进程重启记录在 `logs/service.log`，启动异常另存 `logs/worker-stderr.log`。

点位地图识别已配置老师的完整数字列表，也默认接收群友以“点位更新/最新点位”等标记发布的完整列表，保留实际来源。point_source_senders可指定允许发送无前缀列表的群友。地图不因年龄过期，撤回或改成非点位内容后停用，不回退复活旧列表；历史导入不触发新EA点位快照。

第一版观察条件固定为：

1. 使用最近120根已收盘M5（至少60根），EMA20/50排列及EMA20斜率同向，收盘在EMA20相应方向。
2. 连续三根K线形成“点位另一侧 → 突破至少0.1 ATR → 下一根在点位±0.2 ATR范围回踩并收回”。多空对称。
3. 实时报价距离点位不超过0.75 ATR；结构保护价位于突破/确认两根K线极值外0.25 ATR，距离不超过2.5 ATR；下一老师点位对应收益/风险至少1.2。
4. 报价、同步或点位来源失效则停止候选判断。重启或更换点位后只观察之后形成的突破，不追认旧结构。同一消息版本和M5只保存一次候选提示。

这些是待验证的规则假设，不是盈利结论。界面的结构保护价由算法计算，明确区别于老师原文。候选记录仅用于人工观察，不会进入模拟或实盘交易通道。图片仍待人工识别。

官方接口 [copy_rates_from_pos](https://www.mql5.com/en/docs/python_metatrader5/mt5copyratesfrompos_py) 的索引0是当前K线，因此代码从索引1读取。`mt5_time_offset_seconds` 默认0；本机实测服务器epoch比系统时钟快3小时，私有配置固定为 `-10800`。不根据每条报价自动重算偏移，避免将旧行情当成新行情。报价校验使用读取完成时的本机时间，避免首次IPC连接耗时导致新报价被误判超前；本机实测券商时钟偶尔快5.017秒，未来容差固定为6秒；超过6秒及旧报价仍拒绝，不动态调整时钟偏移。券商时间规则改变后应重新核对，异常时程序停止候选分析。

## 安全门

程序只允许 `mode=monitor` 或 `mode=paper`，没有实盘模式。MT5 适配器只允许 `initialize`、账户/终端/品种/报价/K线读取、`order_calc_profit` 和 `shutdown`。源码和测试会检查不存在交易请求入口。

读取MT5前要求“工具 → 选项 → EA交易”中勾选“禁止通过外部 Python API 自动交易”。本次实测已启用该保护。若关闭，适配器停止行情分析；仅监控模式的飞书读取和看板仍可运行。

## 首次设置

1. 双击 `Setup.cmd`，创建项目虚拟环境并安装固定版本依赖。
2. 双击 `Doctor.cmd`，检查飞书、MT5 保护、账户币种和 XAUUSD.c 报价。
3. 编辑 `%LOCALAPPDATA%\FeishuMT5SignalMonitor\config\config.json`：
   - `mode=monitor` 只读取和分析；`teacher_sender_id` 指定老师身份，`teacher_symbol` 指定点位品种。新版地图不按年龄过期，levels_ttl_seconds只约束旧EA兼容快照（0按24小时处理）。
   - `trusted_senders` 默认空数组，必须由你明确填入可信喊单人的飞书 `open_id` 后，才允许产生纸面模拟订单。
   - `symbols.XAUUSD` 已按当前终端配置为 `XAUUSD.c`。
   - 模拟权益、点差、滑点、风险和有效期均可调低，程序限制其安全上限。
4. 双击 `Start.cmd` 启动，`Status.cmd` 查看状态，`Restart.cmd` 一键等待旧服务退出后重启，`Pause.cmd` 暂停新增同步/成交，`Resume.cmd` 恢复，`Stop.cmd` 优雅停止。
5. 需要登录后自动启动时，先运行 `InstallTask.cmd`。任务计划使用当前交互用户，不保存飞书密钥或 Windows 密码。

看板仅监听本机 `127.0.0.1`，没有远程访问和下单按钮。暂停/恢复使用现有脚本；Windows休眠、退出登录或终端断线期间不能持续获取实时数据。

## 更简单的日常使用

监控只需要双击 `Restart.cmd`。它会先写入优雅停止指令，等待常驻服务关闭看板和监控子进程，再通过任务计划重新启动；不需要手动执行 `Stop.cmd` 和 `Start.cmd`。

EA 不需要每次从导航器拖拽。第一次在目标图表挂载并设置好 `EA_T哥点位跟单` 后，右键图表选择“模板 → 保存模板”，命名为 `Tge跟单`。以后打开相同品种的图表，右键“模板 → 加载模板 → Tge跟单”即可恢复 EA、面板和参数。更换新版 EX5 后，先在 MetaEditor 编译，回到 MT5 的导航器右键“刷新”，再重新加载一次该模板让新 EA 实例生效。

建议把 `Tge跟单.tpl` 保存在 MT5 的 `MQL5\\Profiles\\Templates` 目录；模板由 MT5 自己生成，包含你的图表周期和 EA 参数，不应提交到 Git。模板加载只恢复图表和 EA 配置，不会自动改变终端的算法交易总开关。

## 当前限制

- 默认只解析纯文字；图片、音频和文件会进入待识别/非文字状态，不自动猜测价格。
- 规则解析要求品种、方向、订单类型、止损和止盈明确；不识别隐含或猜测的关联订单。
- 消息编辑、撤回和话题回复会进入复查；来源被编辑后，未成交挂单取消，已持仓保留原保护并标记待核对。
- Python/MT5 IPC 断线、飞书授权过期、报价过期或点差超限时停止新的模拟成交。
- 交易历史是本地估算，采样期间发生的瞬时触价可能因轮询间隔而无法还原。
# 老师点位与原 EA 的可选接口

监控程序每两秒原子导出 `Common/Files/FeishuMT5SignalMonitor/teacher_levels.csv`，只包含已配置老师的中性点位、来源消息版本、品种和有效期，不包含买卖指令。

原 EA 的 `老师点位读取飞书` 现按用户要求默认开启。EA 在定时器读取快照，并沿用原有入场、手数及风控规则；暂停、停止、撤回、编辑尚未重新解析、历史导入、同步失效或品种不匹配时不接受点位，也不回退到旧手填点位。文件心跳最长90秒，来源复查及点位自身有效期可使它更早失效。新点位或断线恢复后等待新的完整M1信号，不追认旧信号。已有图表或旧 `.set` 保存的参数可能覆盖新版默认值。

原 EA 面板状态栏和“专家”日志会区分终端算法交易关闭、EA权限关闭、参数关闭、点位失效、风控限制及等待策略条件。`monitor` 模式仍不产生模拟或真实订单；此接口没有把群友口语喊单变成跟单指令。最后一次有效点位另存 `teacher_levels_display.csv`，仅用于新版 EA 的独立水平线和右上角点位列表；失效时变灰并标明仅供参考，不会回填交易缓存或重新允许开仓。实时入口仍只读取 `teacher_levels.csv`。源码修复与隔离编译不等于已经替换实盘运行版本，也不会打开终端算法交易开关。

## 2026-10-17：WorkBuddy解析入口

新增ai_provider：deepseek（默认，兼容旧配置）或workbuddy。WorkBuddy使用本机已安装的WorkBuddy.exe所附CLI和当前Windows用户的WorkBuddy登录，不提取、复制或另存账号令牌，也不要求DeepSeek Key。当前配置选用GLM-5.3；额度消耗遵循WorkBuddy账号实际计量，并非免费或无限调用。

配置项：

- ai_provider：workbuddy。
- ai_model：glm-5.3，必须是当前WorkBuddy账号可用的模型。
- workbuddy_executable：本机完整路径，例如D:/WorkBuddy/WorkBuddy.exe。
- ai_context_messages：16—512，旧配置默认56，本机调整为256。
- ai_batch_messages：1—32，旧配置默认8，本机调整为16。老师、会议总结和各成员仍分通道处理，会议总结单条解释；不会混淆来源。

监控沿用原有飞书采集和本地消息档案，发现待解析消息才调用WorkBuddy，不需要每隔几秒新建桌面自动化会话。普通空闲轮询不调用模型。每轮阅读有界的相关历史原文、上一份场景和仍有效计划的来源；合格会议总结可进入老师批次的背景，普通群友观点不会升级成老师原话。更早的有效场景原文按引用补回，不能只依赖模型对话记忆。

WorkBuddy调用在临时空目录运行，关闭工具、MCP连接器、项目/用户设置及会话持久化；系统规则从UTF-8临时文件加载，聊天正文经stdin传入，不拼接shell命令。模型仅返回JSON；沿用短消息编号映射、原时点价格补全、方向证据、撤回/版本检查、点位生命周期和6点/5.00间距筛选。超时90秒、额度或登录异常、结果不完整时保留队列退避重试，不把失败当空计划发布，也不自动切回另一个供应商。

网页“重读生成预览”使用同一供应商；预览指纹包含供应商、模型和读取数量，改配置后旧预览不能直接应用。切换供应商不重新入队全部旧消息，不重放旧市价喊单。原有有效计划继续原生命周期；新消息由新入口处理。人工点位编辑/删除保持兼容。

修改运行目录config/config.json后重启监控加载。WorkBuddy需要保持已登录、安装路径有效且账号可用；解析可能需要数十秒，并非逐tick或保证秒级响应。本次没有修改EA源码，不需要重新编译或挂载EA。

验证：本机WorkBuddy登录连接成功，GLM-5.3实际读取监控消息库副本，26.2秒返回完整UPDATE场景、4条方向计划通过原文/版本校验；副本结果未发布到EA。适配器、扩展上下文、会议总结和批量读取相关回归177项通过。另在预览相关测试中发现1项网页发布状态测试失败，改动前基线同样失败，未扩展修改；其余预览测试通过。这些验证不证明模型解释全部正确或能够提高交易收益。

### WorkBuddy连续阅读规则（2026-10-17补充）

WorkBuddy额外阅读规则固定在workbuddy_ai.py的WORKBUDDY_READING_RULES，每轮都注入，不依靠桌面聊天记忆。先按作者权威、消息时间和sequence阅读，再逐个核对旧计划是否被取消、改价或同价新角色替换。普通闲聊不能续期；支撑重申不能当成旧做空重申，压力重申不能当成旧做多重申；不同价的多空参考可以并存。含糊的新交易指令进入REVIEW，不能为了保持开单而猜方向。站稳/跌破等当前协议不能表达的额外条件保留说明，不自动缩成触价计划。

“越读越多”需区分：原始消息档案会累积，单次模型上下文有上限（本机256条，加当前有效场景必要的原始来源），单批新消息本机最多16条。模型会返回完整语义场景，最终执行地图由程序另行筛选：先去掉删除/停用、取消/替换、过期和冲突，再限制最多6个、间距至少5.00。不把语义场景中所有价格直接画到EA上。

默认普通参考依据原确认时点24小时到期，市价提示180秒；原文明示的跨日/半个月期限只作用于相应区间或地图，人工条目按人工配置期限处理。重复解析不刷新确认。模型不自行填写期限，也不因价格远离就删除原文参考。K线破位、点差、报价和交易风控仍由EA既有逻辑检查；本次并未让WorkBuddy实时盯K线。

没有有效报价时，筛选器不会用陈旧现价新增点位；可出现“模型已解析，但执行地图为空/等待报价”。展示预览时须明确区分消息截至时点、语义候选和实际入选地图，不能把旧原文或模型预览称为当前可执行交易建议。
