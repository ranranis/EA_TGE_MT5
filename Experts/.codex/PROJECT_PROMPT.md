# EA v1.56 项目开发提示词

## 工作对象

- 正式主文件是 `Experts/EA_交易托管系统_v1.56.mq5`。
- 用户指定的独立 T 哥跟单 EA 固定使用 `Experts/EA_T哥点位跟单.mq5` 和 `Experts/EA_T哥点位跟单.ex5`；后续开发直接更新这两个根文件，不新建带版本号的主脚本或交付副本。
- T 哥 EA 编译交付时，MetaEditor 输出必须覆盖 `Experts/EA_T哥点位跟单.ex5`；`_dev` 和 `_release` 中的版本副本只能留作历史对照，不能作为当前挂载文件。
- 只沿着主文件的实际 `#include` 关系读取和修改项目源码。
- 旧版、备份、release 和示例文件只用于对照，不能作为当前实现依据。
- `AGENTS.md` 是交易安全和范围边界的最高项目规则。

## 每次任务的执行顺序

1. 先读取 `AGENTS.md` 和本文件，明确允许修改的范围、必须保持的行为和主要回归风险。
2. 搜索真实符号和调用链，至少覆盖相关的 `input`、状态字段、初始化、保存/恢复/删除、事件入口、请求发送、服务器确认、超时、清理和日志。
3. 先用文字说明最小修改方案，再按用户指定范围修改；无关缺陷只报告，不顺手重构。
4. 涉及交易生命周期时，同时遵循 `ea-trade-manager-v156`、`mql5-ea-maintainer` 和 `mql5-trade-lifecycle-auditor`。
5. 修改完成后检查 diff，再进行与改动直接相关的编译、日志或回测验证。

## 验证顺序

- 新会话先通过 MetaEditor MCP 的 `get_workspace_info` 确认工作区。
- MQL5 代码检查优先使用 MetaEditor MCP 的 `syntax_check` 或 `compile_file`，读取完整编译结果和 warning。
- MetaEditor MCP 不可用时，才使用 `mql5-compile-reviewer/scripts/compile-mq5.ps1` 作为备用路径；不得把代码阅读结果当成已编译成功。
- 行为变化需要回测时，使用 MT5 终端 MCP 的测试器和报告工具；只在用户要求或任务确实需要时运行回测。
- 最终报告说明实际修改文件、编译结果、warning、回测结果，以及尚未进行的实盘验证。

## 交易安全边界

- 不新增主动开仓、补仓、马丁、网格或第二套状态机。
- 不擅自修改输入参数、默认值、SL/TP、分批、保本、追踪阈值或中文参数。
- 将候选计算、请求发送、服务器受理和真实持仓/Deal 确认分开。
- `CTrade` 返回 `true` 或请求被受理，不代表成交、修改、平仓或撤单已经完成。
- 以 `POSITION_IDENTIFIER`、`DEAL_POSITION_ID` 和服务器实际状态为准；处理 pending、部分成交、重复事件和重启恢复。
- 突破、箱体确认和结构反转只使用已收盘 K 线；不得用第 0 根替代确认。
- 未经明确要求，不执行真实交易、不修改真实持仓、不加载 EA 到图表进行实盘操作。

## 输出格式

完成代码任务时按以下顺序报告：

1. 修改范围和保持不变的行为。
2. 关键调用链或状态变化。
3. 编译、日志、回测等实际验证结果。
4. 未验证事项和仍存在的直接风险。
