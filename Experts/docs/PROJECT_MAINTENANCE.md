# EA 项目维护制度

适用对象：`EA_交易托管系统_v1.56.mq5` 及其直接引用的项目 Include。

这份制度把用户定位为交易规则负责人和最终验收人，把 Codex 定位为受约束的实现者。用户不需要阅读完整源码，但每次变更都必须能回答：为什么改、改了什么、什么保持不变、如何验证、如何回滚。

## 唯一真相源

- 正式源码只有 `EA_交易托管系统_v1.56.mq5`。
- 直接引用的项目 Include 位于 `Include/`。
- 机制地图位于 `.codex/skills/ea-trade-manager-v156/`。
- 任务状态位于 `docs/tasks/`。
- 编译和基线检查入口位于 `scripts/`。
- `.ex5`、日志、运行 CSV、`.set`、临时备份和发布压缩包不是源码真相源。

旧版、`_backups/`、`Backups/`、`_release/` 和分享简化版只能用于取证或恢复，未经明确决定不能覆盖正式源码。

## 分支与任务

- `main` 只保存用户已经接受的稳定状态。
- 每次只允许一个主要任务处于 `active`，分支使用 `codex/task-<编号>-<短名>`。
- 同一任务只有一个代码写入者；其他代理只能做只读定位。
- 每次只改变一个主要机制。范围外发现进入 `docs/tasks/pending/`。
- 不自动提交、推送、合并或移动标签；这些动作必须取得用户明确授权。

当前仓库根目录是上一级 `MQL5`。只有正式 EA、直接 Include、项目 Skill、任务文档和管理脚本进入版本控制；整个 MT5 数据目录不得执行 `git add .`。

## 标准变更门禁

1. **需求入箱**：复制 `docs/templates/task-template.md` 到 `docs/tasks/inbox/`，保留用户原话。
2. **只读定位**：读取项目 Skill，搜索 input、状态、初始化、持久化、事件入口、请求、确认、清理、日志和图表对象，写出调用链。
3. **风险确认**：平仓、分批、SL/TP、保本、回撤、消息拆锁、手机挂单、重启恢复和 Deal 归属属于高风险，实施前必须获得用户一次明确确认。
4. **任务激活**：证据充分后将任务移入 `active/`；不得同时激活第二个主要任务。
5. **最小实施**：不顺手调参、重命名、格式化或重构无关模块。
6. **执行者自检**：检查范围、input/default、主动开仓能力、状态生命周期、服务器确认、失败/超时和重启路径。
7. **实际编译**：使用 `scripts/compile-mql5.ps1`；以完整日志中的 `Result:` 为准。
8. **用户验收**：用户负责 MT5、模拟盘、面板、手机端和真实券商行为验证。
9. **文档同步**：机制变化时更新项目 Skill 对应 reference；任务完成后移入 `completed/`。
10. **发布**：仅在用户验收并明确授权后提交、打新标签和生成发布清单。

## AI 每次必须交付

- 允许修改范围和明确保持不变的功能。
- 文件、符号和实际调用链。
- 修改文件清单与 diff stat。
- 是否改变 input 名称、中文参数、默认值或主动开仓能力。
- 新状态的初始化、保存、恢复、删除、pending、超时和重启对账覆盖情况。
- MetaEditor 路径、源码、日志、errors、warnings。
- 尚未执行的 MT5/模拟盘/真实交易验证。
- 用户需要亲自验证的场景和准确回滚点。

## 发布与回滚

- 发布前执行 `python -X utf8 scripts/project-baseline.py` 保存源码清单和 SHA-256。
- 发布记录必须绑定 Git 提交、源码哈希、EX5 哈希、编译日志、输入参数文件和用户验收结果。
- 回滚以已确认的 Git 标签为准，不以“final”“new”或某个临时备份文件名为准。
- 发现异常时先停止写入、计算哈希、保留现场；不得直接用旧备份覆盖当前正式文件。

详细验收见 `docs/test-scenarios/regression-matrix.md`，任务字段见 `docs/templates/task-template.md`，发布门禁见 `docs/templates/release-checklist.md`。
